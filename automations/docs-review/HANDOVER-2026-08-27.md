## 5. Other product findings worth carrying

- **The `Live` / `LIVE` convention - resolved, no change needed.** Re-counted 2026-08-27: 184 `LIVE`
  against 21 `Live`, and the two are already doing different jobs. `LIVE` is the state in prose ("while
  the flow is LIVE"); `Live` appears only where the docs quote what is on screen - 9 of the 21 are
  "Live Preview" (a different control entirely), 4 name the "Live chip / badge / status", and the rest sit
  inside HTML verification comments. There is no inconsistency to sweep.
- **Toolbar locators cost three gate rounds.** Verified from tooltips this session:
  `Stop` is the square, second from the left on a LIVE version's toolbar, immediately right of `pause`
  (pause occupies the slot where a Ready version shows play); `Clone` is a toolbar control, **not** on
  the Version Admin tab; `Run Instance` is the lightning icon, and the dialog it opens is titled
  *Launch Flow Instance*. Never write a locator from a note or a DOM dump — read it back against a
  screenshot the page actually ships.
- **Deleting a placeholder is recoverable in one respect**: re-declaring the same name re-points every
  field that read it (independent of the type you give it); the value and description do not come back.
  Driven 2026-08-26.
- **`call-flow-nonblocking.md` - actioned 2026-08-27.** It advised calling with `POST` "when the flow
  needs real numbers, booleans, or structured values", which reads as *a GET cannot carry a number the
  flow can use* - and the 2026-08-24 drives showed `GREATER_THAN` accepting a numeric string on the GET
  route. The wire fact was right and is untouched; the sentence now says only what POST buys you (values
  arrive typed) and claims nothing about which blocks coerce, since no coercion rule has been driven
  across blocks.
